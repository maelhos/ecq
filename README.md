# ECQ

`ECQ` is a library based on [FLINT](https://github.com/flintlib/flint/) to do arithmetic with elliptic curves over $\mathbb Q$. In particular, computing rational points on the curve.

## Descent via $2$-isogeny

For a curve with a rational point of order $2$, `ECQ` performs the first descent, and the second descent when the first one is not conclusive, following

- J. E. Cremona, *Algorithms for Modular Elliptic Curves*
- J. E. Cremona, *Higher Descents on Elliptic Curves*

Curves with no rational $2$-torsion are not handled yet.

## Usage

```bash
make            # release build   -> ./ecq
make debug      # asan + ubsan    -> ./ecq-debug
make test       # regression against tests/out/
make record     # re-record tests/out/
```

The curve is read from stdin as the five coefficients $a_1, a_2, a_3, a_4, a_6$, one per line
(the `mwrank` input format):

```bash
./ecq < tests/curves/test_fruit
```

Set `ECQ_NO_SECOND_DESCENT=1` to run the first descent alone.

## Algorithm setting

**Input:** $E$ an elliptic curve defined by $a_1, a_2, a_3, a_4, a_6$

1. Compute $E_m$, the minimal model, represented by $a_1', a_2', a_3', a_4', a_6'$ of $E$ and let $\varphi : E_m \to E$ the be the corresponding isomorphism. Everything below happens on $E_m$, and the resulting $x$-coordinate is mapped back at the very end by $x = u^2x' + r$.

2. If $a_1' = a_3' = 0$ then
    - Set $s_2 = a_2', s_4 = a_4', s_6 = a_6'$ and $u_{\square} = 1$

   Else
    - Set $s_2 = a_1'^2 + 4a_2', s_4 = 8(a_1'a_3' + 2a_4'), s_6 = 16(a_3'^2 + 4a_6')$ and $u_{\square} = 4$, so that the working variable is $\xi = u_{\square}x'$

3. Iterate over roots $x_0$ of $x^3 + s_2x^2 + s_4x + s_6$

4. $c = 3x_0+s_2, d = (c+s_2)x_0 + s_4, c' = -2c, d' = c^2 - 4d, d'' = c'^2 - 4d' = 16d$

5. If $dd' = 0$ abort

6. Iterate over $d_1$ square-free **divisors of $d$ of either sign** and set $d_2 = d / d_1$. Both signs are needed: the image of the connecting map lies in the subgroup of $\mathbb Q^\ast/(\mathbb Q^\ast)^2$ generated by the divisors of $d$, and $-1$ is one of them as soon as $d < 0$.

7. We are now working over $\mathcal C_{d_1} : y^2 = d_1 x^4 + cx^2 + d_2$ and we have a morphism $\phi_{\mathcal C}: \mathcal C \to E$ being $(u, v) \to (d_1u^2, d_1 uv)$, keep this quartic if it is ELS.

8. Same over $d_1'$ dividing $d'$, giving $\mathcal C'_{d_1'} : y^2 = d_1'x^4 + c'x^2 + d_2'$ and the morphism $\mathcal C' \to E' \to E$, the isogeny being $(x, y) \to (\frac{y^2}{4x^2}, \frac{y(x^2 - d')}{8x^2})$, so that $x_E = \frac{v^2}{4u^2}$.

   Both sides are the same algorithm with $(c, d, d')$ replaced by $(c', d', d'')$, and are run by the same code (`descent_side` in `include/descent.h`).

9. If the second descent is off, search directly on the ELS quartics of steps 7 and 8. Otherwise, for each ELS $\mathcal C_{d_1}$:

10. Solve the conic $y_0^2 = d_1 x_0^2 + cx_0z_0 + d_2z_0^2$

11. Parametrize its solutions by $q_2(u, v)^2 = d_1 q_1(u, v)^2 + cq_1(u, v)q_3(u, v) + d_2q_3(u, v)^2$, so that $(X : Y : Z) = (q_1 : q_2 : q_3)$ and a point of $\mathcal C_{d_1}$ needs $X/Z = q_1/q_3$ to be a square.

    In this normalisation $\mathop{\text{disc}}(q_1) = 4d_2$, $\mathop{\text{disc}}(q_3) = 4d_1$ and $\mathop{\text{Res}}(q_1, q_3) = d'$ (Cremona's are $4\times$ and $16\times$ these).

12. For each square-free $d_3$ dividing $2d'$ (resp. $2d''$), of either sign, **split** the condition as

    $$q_1(\alpha, \beta) = d_3s^2 \qquad q_3(\alpha, \beta) = d_3t^2$$

    Solve the first as a conic and parametrize $(\alpha, \beta, s) = (P_1, P_3, P_2)(\lambda, \mu)$. Substituting into the second gives the descendant

    $$\mathcal D : d_3\\,q_3(P_1, P_3) = (d_3t)^2$$

    Asking only that the *product* $q_1q_3$ be a square would instead give back a curve isomorphic to $\mathcal C_{d_1}$, a degree $2$ covering of $E$ with no height gained. The split makes $\mathcal D \to E$ of degree $4$, a $2$-covering, so its points have about a quarter of the height.

13. Keep $\mathcal D$ if it is ELS, reduce it, and record $Q_i = q_i(P_1, P_3)$. A point $(\lambda, \mu)$ on $\mathcal D$ maps back by $U^2 = Q_1/Q_3$ and $V = Q_2/Q_3$, so

    $$x_E = d_1\frac{Q_1}{Q_3} + x_0 \qquad\text{resp.}\qquad x_E = \frac{Q_2^2}{4Q_1Q_3} + x_0$$

14. Sieve for a rational point on every recorded covering, then map it back to $E$ and lift.

If no $d_3$ gives an ELS descendant, that *proves* $\mathcal C_{d_1}(\mathbb Q) = \emptyset$.

## Checking against other implementations

The Selmer group orders printed as `#S^(phi)(E'/Q)` and `#S^(phi')(E/Q)` are directly comparable
to `mwrank -v1`'s `rk(S^{phi}(E'))` and `rk(S^{phi'}(E))` (as $2^{\text{rk}}$). For
`[0, 67776, 0, 524264742, 7716543824]` both give $16$ and $2$.

The coverings are printed as `[a, b, c, d, e]` meaning $y^2 = ax^4+bx^3+cx^2+dx+e$, with a
copy-pasteable block for Magma:

```text
================= 2-coverings (9) =================
   1  E   2nd     d1 = 42  d3 = -2  [-5276, -10896, 211212, 115200, 687]
   3  E   2nd     d1 = -10560281  d3 = 2  [1385, -22908, 105612, 406184, 557412]
   ...
```

Two quartics define the same covering iff they are $GL_2(\mathbb Q)$-equivalent, which is
detected by their invariants $I = 12ae-3bd+c^2$ and $J = (72ae+9bd-2c^2)c-27(ad^2+b^2e)$ agreeing
up to $(\lambda^4, \lambda^6)$. Against `TwoDescent(E)` in Magma for the curve above, our covers
on the $E$ side reproduce $I = 48332671200$, $J = -19397442280209408$.

Every covering is minimised before being reported, so they all carry the
minimal invariants. On the curve above the minimisation divides out $w = 579$ and
$w = 144346823$ on two of the descendants, taking one of them from 21-digit coefficients
down to `[4708, 13872, -125460, -116016, 491439]`.

**Why the count matches.** By section 3.2.3 the $d_3$ giving an ELS descendant of a given
$\mathcal C_{d_1}$ form one complete coset of $H_1 = S^{(\varphi')}(E/\mathbb Q)/K$, so they
all represent the *same* class in $S^2(E)$: one representative per $d_1$ is enough. `ECQ`
keeps the one with the smallest coefficients (same class, but much easier to sieve) and
reports one covering per $d_1$. For `[0, 67776, 0, 524264742, 7716543824]` that gives $3$
coverings on the $E$ side, matching `TwoDescent(E)`, with $d_1 \in \{42, -10560281,
-443531802\}$ — exactly the non-trivial elements of $S^2(E)$ that `mwrank` reports.
`ECQ_DESCENDANTS=n` keeps $n$ per $d_1$ instead, which only matters if the sieve fails to
find a point on the one kept.

**Known gap:** `bkf_equivalent` only proves equivalence, it cannot prove inequivalence.
Minimal models of a quartic are not unique up to $GL_2(\mathbb Z)$, so two coverings in the
same $S^2(E)$ class can end up as genuinely $GL_2(\mathbb Z)$-inequivalent minimal forms; the
search will not relate them. Deduplication of the covering list therefore goes through the
descent data ($d_1$), not through quartic equivalence.

## Sieving

The point search intersects, for every $Z$, one bit mask per auxiliary prime. That
intersection used to be `fmpz_and` and accounted for most of the running time, so it now
runs on a flat bit vector (`include/bitvec.h`) instead.

`src/bitvec.c` carries three implementations of the limb kernels — AVX-512, AVX2 and a
portable scalar one — written once against a small set of macros and selected at compile
time from the target's feature macros, so `-march=native` picks the best the machine has.
Measured on a Zen 3 (AVX2, no AVX-512):

| kernel | `bv_and_into` |
| --- | --- |
| scalar | 13.1 GB/s |
| AVX2 | 40.7 GB/s |

and against the old `fmpz` sieve, end to end: `62.9 s -> 1.0 s` on `tests/curves/goal`.

## Hard test curves

The congruent number curves $y^2 = x^3 - n^2x$ have full $2$-torsion and, for $n$ large,
generators of very large canonical height, so they make good stress tests.
`python/find_hard_curves.py` scans them, predicting the height from BSD
($\mathrm{Reg} = L'(E,1)\,|E_{tors}|^2 / (\Omega \prod_p c_p)$ for analytic rank $1$)
instead of looking for the generator, which is the expensive part being tested.

Verified, with the height of the point `ECQ` actually returns:

| curve | $n$ | $\hat h$ | time |
| --- | --- | --- | --- |
| `tests/curves/goal` | 10239 | 87.24 | 1.0 s |
| `tests/curves/cn_10381` | 10381 | 95.30 | 1.8 s |
| `tests/curves/harder` | — | 98.59 | 0.8 s |
| `[0,0,0,-105945849,0]` | 10293 | 99.67 | 164 s |
| `[0,0,0,-106626276,0]` | 10326 | 103.60 | 42 s |
| `[0,0,0,-122168809,0]` | 11053 | 106.17 (predicted) | not found in 100 s |

The running time is not a function of the canonical height alone: it depends on the naive
height of the point on the particular covering the sieve happens to be handed, which is why
10326 is found much faster than 10293 despite being higher.

Predicted heights in the range $10000 < n < 12000$ alone go past $1100$, so there is plenty
of room left to stress the search.
